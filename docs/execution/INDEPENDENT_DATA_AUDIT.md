# Independent data-path review

Reviewed 2026-09-11 by the independent metrics/verifier agent. Source inspection: `data.py`, `geometry.py`, `acquisition.py`, preparation script, metadata and existing audit artifacts. No sealed-test images, targets or predictions were inspected; only manifest counts describe test preparation.

## Verified pathway

- XML object IDs **13 car** and **19 pedestrian** are correct for the released bounding-primitive files, verified against the XML's human-readable `label` entries for both training drives. These are a separate taxonomy from semantic PLY ground IDs: 7 road, 8 sidewalk, 9 parking, 10 rail track and 22 terrain.
- XML local vertices are transformed into world space, then into ego coordinates. The box geometric center, dimensions and upright heading are derived from those vertices. The pose-axis conversion is forward/left/up and camera extrinsics consistently include that basis change.
- Native Mei fisheye calibration retains xi, radial and tangential distortion, half-pixel-aware resize intrinsics, inverse camera rays and the physically valid Mei projection branch. Perspective rectification is included in camera extrinsics; each perspective camera's own translation supplies the stereo baseline.
- Depth labels are nearest current radial LiDAR returns in image-feature cells, masked outside 1..80m. Road targets use current-view-supported accumulated static ground points; unsupported cells stay -1. This is sparse visible-surface supervision, not dense road completion or exhaustive instance annotation.
- Dynamic object boxes become positives only at their exact annotated timestamp, restricted to the annotation window and current LiDAR/camera support. Other dynamic timestamps mask their unsupported footprints. Instance IDs remain annotations/metrics, not inference inputs.
- Existing geometry controls pass: **7 tests**. Published audit roundtrip maximum is **0.0001304 pixels**, although self-consistency alone cannot certify extrinsics. Independent visual inspection of train0000/frame1105 and validation0003/frame640 projected-box audit images confirms representative object alignment in perspective and fisheye views. This is two reviewed timestamps, not a claim that all 50 audit images passed visual review.
- Dynamic heading sanity check against actual inter-annotation world displacement: train0000 cars 2014/2016 eligible moving pairs within45 degrees; train0002 cars812/819; val0003 cars983/985. Pairs require displacement>=0.3m and timestamp gap1..10 frames. This supports the heading-axis convention; it is not model evaluation.

## Material limitations and ordered actions

1. **Validation cannot establish pedestrian generalization.** Drive0003 contains exactly one annotated pedestrian identity. At the full 2Hz selection, only7 possible in-range boxes/frames remain even before visibility filtering (630,635,640,645,650,655,660). The completed smoke set retained one. A full download cannot add pedestrian diversity to this drive. Report these counts, avoid strong person-performance conclusions, and do not tune repeatedly to that one identity. An expanded independent validation drive/route would require a separately documented split decision; sealed0004 must remain untouched during tuning.
2. **Freeze manifest provenance per training/evaluation run.** Preparation replaces `manifest.json`; training captures rows at dataset construction while each validation dataset can be newly constructed. Mixing smoke/full versions between epochs invalidates checkpoint comparisons. Use immutable named manifest paths and record hashes before scored training.
3. **Road/rendering origin needs a calibrated offset.** Training pedestrian0000/frame1105 has center z=-0.298m, height2.089m, hence base z=-1.343m. The ego pose origin is above ground; a renderer plane at z=0 is inconsistent. The authorized viewer correction adds static metadata `ground_z`, default -1.5m explicitly provisional. Use training-only calibration to refine it. Shift the plane/reference asset together; do not change predicted object coordinates or derive plane height from sealed-test annotations.
4. **Drive holdout is not complete geographic holdout.** Across1010 validation poses,67 are within5m,89 within20m and128 within50m of training0000/0002 poses. Overlap is within validationframes1..94; median nearest-training distance453.9m. Pedestrian frames630..660 are635..687m from training poses. Consider reporting a novel-area breakdown alongside whole-drive metrics if claiming unseen-location generalization; do not silently modify the approved split.
5. **Sparse masks limit metric scope.** Ground-derived negative regions and exact-time boxes are conservative but do not prove all cars/people are exhaustively labeled in a surround frame. Preserve detection validity during loss and evaluation; describe the scores as custom supported-region subset metrics. Do not equate them with official KITTI AP or full-surround recall. Retained positives must always remain evaluable even if a validity mask is false.
6. **Acquisition hashes are recorded but resume trusts existing members.** New selected ZIP members are CRC checked and stored/source SHA256 recorded. Resume currently skips a recorded member if its output exists, without recomputing its stored hash. A separate pretraining integrity pass should verify stored sizes/hashes, especially after interrupted preparation. This is a robustness gap, not evidence of current corruption.
